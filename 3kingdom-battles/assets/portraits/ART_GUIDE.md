# 三國・名戰錄　武將頭像美術規範（模板 v2）

本文件規範所有武將頭像的畫風、規格、生成流程與授權紀錄。
人物資料與生成模板寫在 `characters.js`，生成紀錄寫在 `log.json`，相關工具是 `../../tools/portraits.js`。

## 1. 現況：頭像在遊戲裡怎麼用

| 位置 | 顯示大小 | 用到的情緒 |
|---|---|---|
| 戰前說明「登場武將」 | 72px | 平常 |
| 武將錄（點頭像開啟） | 120px | 平常＋演義中寫到的情緒 |
| 部隊資訊卡 | 52px | 平常 |
| 事件視窗（獻策、水淹、倒戈…） | 72px | 依事件 |
| 單挑／技能特寫 | 96px | 勝：笑或怒，敗：憔悴或哭 |
| 結局（白門樓群像） | 72px | 依結局 |

**最小顯示 52px**，所以 1024px 原圖必須在縮小到 1/20 時仍然認得出是誰。辨識要靠剪影、髮鬚、冠帽和主色，不能靠細節。

目前所有頭像都是 `js/portraits.js` 畫的 SVG。PNG 經審核通過（`status: 'approved'`）後會自動取代 SVG，載入失敗時也會退回 SVG。

## 2. 整體美術方向

**東方歷史奇幻・半寫實數位繪畫。**

- **厚重感**：歷史策略遊戲的沉穩基調，不走輕快卡通，也不走華麗手遊。
- **辨識度**：每位武將要有一個縮小後仍看得出的「招牌」，例如關羽的長髯與綠巾、張飛的虎鬚、呂布的紫金冠、夏侯惇的眼罩、諸葛亮的綸巾鶴氅。
- **時代考據**：以漢末（約西元 200 年）的服飾與甲冑為參考，例如交領右衽、進賢冠、綸巾、札甲、魚鱗甲、環鎖鎧，可以適度美化，但不要混入日本武士甲、明清服飾或辮髮。
- **審美**：主角群照現代審美畫得好看；能力平平或演義寫明相貌普通的部將（侯成、宋憲、魏續）畫得普通些，但不醜化。
- **人物設計獨立**：依演義的公共領域文字與性格重新設計臉、服裝、甲冑和配色，不參照任何現有作品的造型。

## 3. 固定生成模板（所有人物共用，不得改動）

完整英文版在 `characters.js` 的 `TEMPLATE`。每位人物只能改「外貌、年齡、服裝、盔甲、配色、表情」這六項，其餘不得改動。

| 項目 | 規範 |
|---|---|
| 畫風 | 半寫實數位繪畫，帶筆觸的細緻描繪；歷史策略遊戲的厚重基調 |
| 光線 | 左上約 45° 的柔和主光，暗側補光；右後方淡暖色輪廓光把人物和背景分開；有電影感但節制，不要魔法光 |
| 構圖 | 肩部以上胸像，單人置中，身體朝畫面左側約 3/4 側面；雙眼約在畫面上方 40% 處；頭頂距上緣至少 10%，雙肩完整入鏡、兩側留白 |
| 色彩 | 自然、沉穩、低飽和；皮膚與皮革用暖色調，服裝只用該人物的配色 |
| 臉部 | 五官清楚、比例自然、有皮膚質感，焦點在眼睛；縮小到 64px 仍看得出表情 |
| 背景 | 簡潔的暗色柔焦漸層，帶淡淡霧氣；不要景物、文字或物件；人物和背景的明度對比要夠 |
| 禁止（負面提示詞） | 文字、書法、標誌、浮水印、簽名、邊框、UI；多人、多餘肢體或手指、臉部變形；頭部被裁切或貼邊；全身像；動漫、Q 版、卡通、3D 算圖、塑膠皮膚、照片、cosplay；過飽和、霓虹、魔法光效、鏡頭光暈、雜亂背景；日本武士甲、清朝辮髮、明朝服飾、現代服裝；任何真人演員的長相；任何現有遊戲、電影、電視劇或漫畫的角色造型 |

**提示詞不放人名。** 模型看到「Guan Yu」這類名字，容易套用它學過的現有遊戲或影視造型，所以只用外貌描述生成，人名只記在資料裡。

## 4. 圖片規格

- **格式與尺寸**：PNG，1024 × 1024。
- **構圖與背景**：肩部以上或胸像，人物置中；背景簡潔，不得有文字、標誌、浮水印或簽名。
- **光線與色彩**：柔和主光加適度輪廓光；色彩自然沉穩，不要過度飽和。
- **對比與留白**：人物和背景要有足夠對比，方便放在遊戲 UI 上；預留裁切空間，頭和肩不可貼邊（遊戲會裁成圓角方形）。

## 5. 檔名與對應規則（避免載入錯誤）

1. **人物 id**：一律用 `js/data.js` 的 `GENERALS` 鍵，例如 `guanyu`、`lubu`。
2. **檔名**：主圖是 `<id>.png`，情緒圖是 `<id>__<情緒>.png`；情緒鍵要和 `js/portraits.js` 的 `MOODS` 相同，例如 `lubu__plead.png`。
3. **何時載入**：只有 `status: 'approved'` 的圖片會被遊戲載入。
4. **自動檢查**：`node tools/portraits.js check`（測試也會跑）會擋下以下情況：
   - id 不在遊戲裡，或名字不一致
   - 檔名不合規則
   - 標成已生成或已審核，但檔案不存在
   - 不是 PNG，或不是 1024×1024
   - 沒有生成紀錄，或紀錄缺欄位
   - 圖片內容和紀錄的 sha256 不同
   - 資料夾裡有對不到人物的圖片

## 6. 生成與審核流程

1. **產生提示詞**：執行 `node tools/portraits.js prompts`，產生 `prompts/<id>.txt`，內容是模板加上該角色的正向與負面提示詞。
2. **生成候選圖**：每位人物生成 3～4 張候選，只用文字提示，**不使用任何現有角色圖片當參考圖**。
3. **入庫**：挑出一張後執行：
   ```bash
   node tools/portraits.js import guanyu 挑好的圖.png --model "模型名稱與版本" --source "text prompt only" --license "服務條款名稱／網址" [--seed 123]
   ```
   JPG、WebP 或不是 1024×1024 的圖會自動置中裁成正方形、轉成 1024×1024 PNG；短邊小於 768 的不收。
   這個指令會改成規定檔名，並寫入 `log.json`。紀錄欄位包括：日期、模型、提示詞、負面提示詞、種子、模板版本、素材來源、授權、sha256。
4. **審核**：在 `characters.js` 把 status 改成 `generated`，執行 `node tools/portraits.js sheet` 產生縮小對照表（256／96／72／52／32px），逐項檢查：
   - 52px 時還認得出是誰嗎？
   - 六張並排時，畫風、光線方向和構圖一致嗎？
   - 有沒有文字、浮水印或手指錯誤？
   - 看起來像不像某部現有作品的角色？
5. **通過或不採用**：通過就把 status 改成 `approved`，遊戲會自動載入；不通過就改成 `rejected`，或回到第 2 步重新生成。

**第一批**：劉備、關羽、張飛、曹操、諸葛亮、趙雲六張，可以直接複製的提示詞在 `prompts/batch1.md`（含 ChatGPT 與 Midjourney 版本）。確認風格後，再做第 1 關其他武將（第二批），最後做情緒圖。

## 7. 挑圖標準（以多數人審美為準）

候選圖依下表逐項比較，前三項只要有一項不合格，就不論其他項表現直接淘汰：

| 順序 | 項目 | 看什麼 |
|---|---|---|
| 1 | 沒有瑕疵 | 沒有文字、浮水印、多餘手指或肢體；五官不歪、雙眼對稱；頭和肩沒被裁切 |
| 2 | 符合設定 | 演義的招牌特徵都在（例如長髯、紫金冠、眼罩），年齡、服裝、配色都對 |
| 3 | 不像現有作品 | 不像任何遊戲、影視、漫畫角色或真人演員 |
| 4 | 好看（多數人審美） | 五官勻稱、輪廓清楚、眼睛有神、皮膚乾淨；髮鬚整齊；表情自然有氣質；主角群偏帥氣英挺，部將普通但不醜 |
| 5 | 縮小辨識度 | 52px 時仍看得出是誰，剪影、髮鬚、冠帽、主色要清楚 |
| 6 | 一致性 | 和已入選的頭像比，光線方向、畫風、構圖和背景明暗要一致 |

前三項都合格的候選圖，依第 4～6 項的優劣排序，取第一名。
如果所有候選都不合格，就微調該角色的 `design` 重新生成，**不調整共用模板**。
